## 도입 이야기 가이드 (00-03분)

### 배경 지식: 교사가 알아두면 좋은 것

**토큰화(Tokenization)와 임베딩(Embedding)**
- **토큰화**: 문장을 작은 조각(토큰)으로 쪼개는 과정. 단어일 수도 있고, 단어의 일부일 수도 있음
  - 가장 널리 쓰이는 방법: BPE(Byte Pair Encoding) — 자주 붙어 나오는 글자 쌍을 합치는 방식
  - GPT-4의 토크나이저는 약 10만 개의 토큰을 보유
  - 한국어는 영어보다 토큰이 2~3배 더 많이 필요 → 비용, 속도, 품질에 영향

- **임베딩**: 각 토큰을 의미가 담긴 숫자 벡터로 변환하는 것
  - 원-핫 인코딩의 한계: 10만 차원, 모든 단어 간 거리가 동일 → 의미 관계 표현 불가
  - Word2Vec (2013, Mikolov): 수백 차원의 밀집 벡터로 의미를 압축
  - 핵심 원리: 분포 가설(distributional hypothesis) — "비슷한 맥락에서 등장하는 단어는 비슷한 의미를 가진다"
  - 학습 방법: 2~6차시에서 배운 신경망 + 손실함수 + 역전파와 동일한 원리

- **Word2Vec의 두 가지 방식**
  - CBOW: 주변 단어 → 가운데 단어 예측 (더 빠름)
  - Skip-gram: 가운데 단어 → 주변 단어 예측 (드문 단어에 강함)
  - 실제 GPT 등 최신 모델은 문맥별로 다른 임베딩(contextualized embedding)을 사용 → 8차시에서 다룸

**학생에게 어느 정도까지 말할 것인가:**
- BPE 원리 → 교과서 심화 박스에 있음. 학생이 물으면 "자주 나오는 쌍을 합치는 방식"으로 간결하게
- Word2Vec 이름, 미콜로프 → 역사 공개 파트에서
- 분포 가설 → 이론 설명 중에 핵심으로 전달
- CBOW/Skip-gram → 심화 학생에게만 간략히

### 교사 멘트

> "어떤 연구자가 단어를 숫자로 바꾸는 방법을 발견했을 때, 이상한 일이 일어났어요. 컴퓨터에게 '왕'이라는 단어에서 '남자'를 빼고 '여자'를 더하라고 했더니 — '여왕'이 나온 겁니다."

> "컴퓨터가 의미를 이해하는 걸까요? 오늘 여러분이 직접 확인해봅시다."

### 학생 예상 반응

| 반응 | 대응 |
|------|------|
| "진짜요? 어떻게요?" | "그게 오늘의 미스터리예요. 수업 끝나면 알 수 있어요." |
| "단어를 빼고 더하는 게 가능해요?" | "숫자로 바꾸면 가능합니다. 어떻게 숫자로 바꾸는지부터 알아봅시다." |
| "당연히 여왕이죠" | "사람한테는 당연하지만, 숫자밖에 모르는 컴퓨터가 이걸 해낸다는 게 놀라운 거예요." |

**주의:** "왕 - 남자 + 여자 = 여왕"은 이 수업 전체의 킬러 예시입니다. 도입에서 호기심만 유발하고, 왜 이것이 가능한지에 대한 설명은 수업 후반부까지 미루세요. 이것이 긴장감을 유지하는 핵심입니다.

## 실습1: 토큰화 대결 가이드 (03-15분)

### 교사 멘트 — 문제 제기

> "6차시까지 우리는 신경망이 숫자를 입력받아 숫자를 출력하는 기계라는 것을 배웠어요. 그런데 여러분은 매일 ChatGPT에게 '글'로 질문하잖아요. 숫자밖에 모르는 기계가 어떻게 글을 처리하는 걸까요?"

> "그 비밀의 첫 번째 단계가 **토큰화**예요. 문장을 작은 조각으로 쪼개는 거예요. 직접 해봅시다."

### 토큰화 실습 진행

**진행 순서:**
1. TokenizerPlayground 시뮬레이터를 열게 한다
2. "안녕하세요"를 입력 → 토큰 수 예상 vs 실제 비교
3. 같은 의미 영어 "Hello" 입력 → 토큰 수 차이 관찰
4. 이모지 입력 → 이것도 토큰으로 처리됨을 확인
5. **대결:** "가장 적은 토큰으로 '오늘 점심 뭐 먹었어?'와 같은 의미를 전달하는 문장 만들기"

#### 교사 멘트 — 1단계 (안녕하세요)

> "'안녕하세요'를 입력하기 전에, 이 문장이 몇 개의 토큰으로 나뉠지 예상해보세요. 1개? 2개? 5개?"

(학생 예상을 2~3명 받은 뒤)

> "자, 입력해봅시다."

(학생이 입력한 후)

> "예상과 다르죠? 한 단어인데 토큰이 여러 개로 나뉘었어요. 왜 그런지는 잠시 후에 설명할게요."

#### 교사 멘트 — 2단계 (한국어 vs 영어)

> "이번엔 같은 의미의 영어 'Hello'를 입력해보세요."

(학생 반응을 기다림)

> "한국어 '안녕하세요'가 토큰이 여러 개인데, 영어 'Hello'는 하나라고요? 이건 단순한 기술 차이가 아니에요."

> "AI에게 같은 질문을 해도 한국어는 토큰이 더 많이 들어서, **비용도 더 들고 처리 속도도 느려질 수 있어요**. AI 시대에 언어 간 형평성이라는 새로운 문제가 생긴 겁니다."

#### 교사 멘트 — 3단계 (대결)

> "자, 이제 대결합니다! '오늘 점심 뭐 먹었어?'와 같은 의미를 전달하되, **가장 적은 토큰**으로 표현하는 문장을 만들어보세요. 2분 줄게요."

(2분 후)

> "가장 적은 토큰 수를 가진 학생, 발표해보세요. 몇 개로 줄였어요?"

### 학생 예상 반응 (토큰화 실습 중)

| 반응 | 대응 |
|------|------|
| "한국어가 왜 토큰이 더 많아요?" | "현재 대부분의 AI가 영어 중심으로 학습되었기 때문이에요. 영어 단어는 자주 나와서 통째로 하나의 토큰이 되지만, 한국어 글자 조합은 상대적으로 드물어서 더 잘게 나뉘는 거예요." |
| "이모지도 토큰이에요?" | "네! 컴퓨터에게는 글자든 이모지든 전부 처리해야 할 데이터예요. 이모지 하나가 토큰 하나 이상을 차지합니다." |
| "영어가 유리한 거 아니에요?" | "맞아요. 같은 의미를 전달하는데 한국어가 토큰을 더 많이 쓰니까, 비용도 더 들고 처리도 느려질 수 있어요. 이게 AI 시대의 새로운 언어 불평등 문제예요." |
| "줄여도 5개 이하로 안 내려가요" | "한국어의 구조적 특성이에요. 영어로 같은 뜻을 표현하면 토큰이 더 적을 수 있어요." |

### 시뮬레이터 운영 상세: TokenizerPlayground

| 항목 | 내용 |
|------|------|
| **소요 시간** | 약 10-12분 |
| **주요 기능** | 문장 입력 → 토큰 분리 시각화, 토큰 수 표시 |
| **교사 팁** | "한국어 vs 영어" 비교를 반드시 포함하세요. 학생들의 서프라이즈 반응이 가장 큰 순간입니다 |
| **추천 입력 예시** | "안녕하세요", "Hello", "인공지능", "Artificial Intelligence", "나는 오늘 점심을 먹었다" |

**운영 팁:** 토큰화 대결은 자연스럽게 경쟁심을 유발합니다. 2-3분 시간을 주고, "가장 적은 토큰 수"를 보고한 학생의 문장을 공유하세요.

## 이론 설명 가이드 (15-28분)

### 토큰 번호의 한계 (15-18분)

#### 교사 멘트

> "토큰으로 쪼갠 뒤, 각 토큰에 고유한 번호를 붙여요. 예를 들어 'love'가 2834번, 'hate'가 7291번."

> "그런데 질문. 이 번호에서 'love'와 'hate'가 **반대 의미**라는 걸 알 수 있나요? 2834와 7291이라는 숫자만 보고?"

(학생 반응을 기다림 — 대부분 "없어요")

> "맞아요. 토큰 번호는 그냥 출석 번호 같은 거예요. 출석 번호 1번과 30번이라고 해서 뭔가 관계가 있는 건 아니잖아요."

> "그러면 단어의 의미를 숫자로 표현하려면 어떻게 해야 할까요?"

### 임베딩의 등장 (18-23분)

#### 교사 멘트

> "숫자 하나로는 안 돼요. **여러 개의 숫자 묶음**으로 표현해야 해요. 이걸 **벡터**라고 하고, 이 변환을 **임베딩(embedding)**이라고 합니다."

> "비유하자면, 토큰 번호는 출석 번호이고, 임베딩은 **프로필 카드**예요. 운동 잘하는 정도, 공부 잘하는 정도, 키... 여러 특성을 숫자로 적으면, 비슷한 사람끼리 비슷한 카드를 가지게 되죠."

(칠판에 벡터 연산 예시를 적으며)

```
왕   = [0.9, 0.9, 0.2]
여왕 = [0.9, 0.2, 0.2]
남자 = [0.2, 0.9, 0.1]
여자 = [0.2, 0.2, 0.1]
```

> "'왕'과 '여왕'은 왕족이라는 의미가 같으니까, 벡터의 첫 번째 값(0.9)이 비슷해요. '왕'과 '남자'는 성별이 같으니까, 두 번째 값(0.9)이 비슷해요."

> "핵심은 이거예요. **의미가 비슷한 단어는 비슷한 숫자를 가진다.** 이 숫자 묶음을 좌표로 생각하면, 단어들이 공간의 한 점에 배치돼요. 의미가 가까우면 가까이, 멀면 멀리."

### 벡터 연산 (23-25분)

#### 교사 멘트

> "자, 이제 아까 도입에서 던졌던 미스터리를 풀 차례예요."

(칠판에서 계산하며)

> "왕 - 남자 + 여자를 벡터로 계산하면..."

> "[0.9, 0.9, 0.2] - [0.2, 0.9, 0.1] + [0.2, 0.2, 0.1] = [0.9, 0.2, 0.2]"

> "이 결과 [0.9, 0.2, 0.2]는 — **여왕의 벡터와 정확히 같습니다!**"

> "어떻게 이런 일이 가능할까요? '왕'에서 '남자'를 빼면, 남는 건 '왕족이라는 의미'예요. 거기에 '여자'를 더하면 '여성 왕족', 즉 '여왕'이 되는 거예요."

### 학생 예상 반응 (이론 설명 중)

| 반응 | 대응 |
|------|------|
| "임베딩 벡터의 각 숫자는 무슨 뜻인가요?" | "사람이 '왕족 차원', '성별 차원' 같은 것을 정해준 게 아닙니다. 기계가 데이터에서 패턴을 찾아 스스로 만든 거예요. 각 차원이 뭘 뜻하는지 사람이 정확히 해석하기 어려운 경우가 많아요." |
| "'왕 - 남자 + 여자 = 여왕'이 항상 맞나요?" | "항상 완벽하진 않아요. 하지만 많은 경우에 놀라울 정도로 잘 맞습니다. 핵심은 100% 정확한가가 아니라, 단어의 관계가 벡터의 방향으로 포착된다는 것 자체가 혁명적이었다는 거예요." |
| "이 숫자는 누가 정한 거예요?" | "사람이 아니라 기계가 학습한 거예요! 2~6차시에서 배운 신경망, 손실함수, 역전파가 여기서도 쓰여요." |

### "이 숫자는 누가 정했을까?" — 핵심 전환점 (25-28분)

#### 교사 멘트

> "여기서 중요한 질문. '왕'이 [0.9, 0.9, 0.2]라는 벡터를 가진다고 했는데, **이 숫자는 누가 정한 걸까요?** 사람이 '왕은 왕족이니까 0.9'라고 정한 걸까요?"

(2초 대기)

> "아닙니다. **기계가 스스로 학습한 거예요.** 핵심 아이디어는 놀랍도록 간단해요."

> "'한 단어의 의미는 그 단어의 주변 단어들이 결정한다.' '왕' 주변에는 '왕관', '왕좌', '통치' 같은 단어가 자주 나타나요. '여왕' 주변에도 비슷한 단어가 나타나죠. 주변 단어의 패턴이 비슷하면, 그 단어들의 의미도 비슷하다고 판단하는 거예요."

> "이것을 **분포 가설**이라고 불러요. '비슷한 맥락에서 등장하는 단어는 비슷한 의미를 가진다.'"

## 차시 연결

### 이전 차시 (6차시) 복습 포인트

> "지난 시간까지 우리는 신경망이 숫자를 입력받아 숫자를 출력하고, 역전파로 학습하는 과정을 배웠어요. 그런데 한 가지 이상한 점이 있죠 — 여러분은 매일 AI에게 글자로 질문하잖아요. 숫자밖에 모르는 기계에게 글자를 어떻게 건네줄까요?"

- 2~6차시 전체가 "숫자 → 숫자" 처리였음을 한 줄로 정리합니다
- "글자 → 숫자" 변환이라는 새로운 문제를 제기합니다

### 다음 차시 (8차시) 예고 포인트

> "토큰화로 쪼개고, 임베딩으로 숫자로 바꾸는 것까지 배웠어요. 그런데 AI는 이 숫자들로 정확히 **무엇을** 할까요?"

> "놀랍게도, AI가 하는 일의 본질은 딱 하나 — **'다음 단어를 맞추는 것'**입니다. 그것만으로 번역, 글쓰기, 코딩, 대화가 모두 가능하다면? 다음 시간에 확인합니다."

- 토큰화+임베딩이 "다리" 역할임을 강조합니다
- 8차시의 "다음 단어 예측"이라는 핵심 원리에 대한 기대감을 유발합니다
- 1차시의 "기계가 생각할 수 있는가?" 질문이 8차시에서 더 구체적인 답을 얻게 된다는 점을 암시합니다

**교사 메모:** 7차시는 Part 3(학습의 원리)에서 Part 4(언어를 이해하는 AI)로 넘어가는 전환점입니다. 2~6차시에서 배운 "숫자 → 숫자" 처리 원리가 "글자 → 숫자" 변환을 통해 언어에도 적용된다는 연결이 핵심입니다. "왕 - 남자 + 여자 = 여왕"은 학생들에게 가장 강렬한 인상을 남기는 예시이므로, 도입에서 던지고 수업 후반에 해결하는 구조를 반드시 유지하세요. 임베딩 갤럭시에서 학생들이 자유롭게 탐험하는 시간을 충분히 주되, 중간에 한 번은 "가장 놀라웠던 배치"를 공유하는 시간을 만들어 관찰의 질을 높이세요.

**오답 해설:**

- ③ 글자에 부여된 숫자 코드는 "토큰 번호(토큰 ID)"이지 토큰 자체가 아닙니다.
- ④ 임베딩 벡터는 토큰에 의미를 부여한 숫자 묶음으로, 토큰과 다릅니다.

### 문제 4. 벡터 연산 (단답형)

**정답:**

파리 - 프랑스 + 일본

= [0.8, 0.9, 0.3] - [0.2, 0.9, 0.3] + [0.2, 0.1, 0.3]

= **[0.8, 0.1, 0.3]**

→ 이 벡터와 가장 가까운 단어는 **도쿄** ([0.8, 0.1, 0.3]과 일치)

### 문제 5. 임베딩의 핵심 원리 (서술형)

**예시 답안**:

토큰 번호는 사전에서의 순서를 나타내는 숫자 하나일 뿐이므로, "좋다/싫다", "동물/식물" 같은 여러 의미 차원을 담을 수 없습니다. 반면 임베딩 벡터는 여러 개의 숫자 묶음(벡터)으로 단어를 표현하여, 각 숫자가 서로 다른 의미 차원을 담습니다. 그 결과 **의미가 비슷한 단어**끼리는 비슷한 벡터를 가지게 되어 가까이 배치되고, 의미가 다른 단어끼리는 멀리 배치됩니다. 이렇게 단어의 의미 관계가 벡터 공간의 거리와 방향으로 표현되기 때문에, "왕 - 남자 + 여자 = 여왕" 같은 의미 연산이 가능해집니다.

**채점 기준 (루브릭)**:

| 수준 | 기준 | 배점 |
|------|------|------|
| 상(5점) | 토큰 번호의 한계(단일 숫자, 의미 정보 없음)와 임베딩의 장점(여러 숫자, 의미 차원)을 대비하여 설명하고, "의미가 비슷한 단어"가 가까운 벡터를 가진다는 핵심을 정확히 서술 | 5 |
| 중(3점) | 토큰 번호와 임베딩의 차이를 설명하고, "의미가 비슷한 단어" 표현을 포함하나 설명이 다소 피상적 | 3 |
| 하(1점) | 임베딩이 숫자 묶음이라는 것은 알지만, 토큰 번호와의 차이나 의미 표현 원리를 구체적으로 설명하지 못함 | 1 |

### 문제 6. 분포 가설 (서술형)

**예시 답안**:

분포 가설이란 "비슷한 맥락에서 등장하는 단어는 비슷한 의미를 가진다"는 원리입니다. 기계는 거대한 텍스트 데이터에서 각 단어의 주변 단어 패턴을 분석하여 임베딩 벡터를 학습합니다.

"왕"이라는 단어 주변에는 "왕관", "왕좌", "국가", "통치" 같은 단어가 자주 등장하고, "여왕" 주변에도 비슷한 단어들이 나타납니다. 주변 단어의 패턴이 비슷하므로, 분포 가설에 따라 기계는 "왕"과 "여왕"에 비슷한 임베딩 벡터를 부여하게 됩니다. 이 학습 과정에서 2~6차시에서 배운 신경망, 손실함수, 역전파가 동일하게 사용됩니다.

**채점 기준 (루브릭)**:

| 수준 | 기준 | 배점 |
|------|------|------|
| 상(5점) | 분포 가설의 정의를 정확히 서술하고, "왕"과 "여왕"의 주변 단어 패턴이 비슷하다는 구체적 예시를 들어 설명. 학습 원리(신경망, 역전파 등)와의 연결까지 언급하면 만점 | 5 |
| 중(3점) | 분포 가설의 핵심(주변 단어 패턴 → 의미 유사성)을 설명하고, "왕"과 "여왕"의 사례에 적용했으나 구체적 예시가 부족 | 3 |
| 하(1점) | 분포 가설의 의미를 대략 이해하나, "왕"과 "여왕"의 사례 적용이 불명확하거나 피상적 | 1 |
