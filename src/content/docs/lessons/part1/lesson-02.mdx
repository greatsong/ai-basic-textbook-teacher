## 뉴런과 퍼셉트론 소개 가이드 (슬라이드 #5~9)

### 배경 지식: 교사가 알아두면 좋은 것

**맥컬록-피츠 모델 (1943)**
- 신경과학자 워런 맥컬록과 수학자 월터 피츠가 제안
- 핵심 통찰: 뉴런은 발화하거나(1) 안 하거나(0) → 논리 연산(AND, OR, NOT)과 같다
- 세계 최초의 인공 뉴런 모델이지만, **자동 학습 기능이 없었음** (사람이 가중치를 직접 설정)
- 월터 피츠는 12세에 러셀의 *Principia Mathematica*를 읽고 오류를 발견한 천재 → 학생에게 흥미 포인트로 활용 가능

**프랭크 로젠블랫 (1928-1971)**
- 코넬 항공연구소의 심리학자
- 1958년 퍼셉트론(Perceptron) 발명 — 맥컬록-피츠에 **"학습"을 추가**한 것이 핵심
- Mark I 퍼셉트론: 실제 하드웨어로 제작된 기계. 5x5 격자의 빛 패턴을 읽어 글자 구별
- 학습 이미지 20장만으로 X와 O를 100% 구별, E와 F도 80% 이상 맞힘
- 비극적으로 43세에 보트 사고로 사망 (1971년)

**학생에게 어느 정도까지 말할 것인가:**
- 뉴런의 구조 (수상돌기, 세포체, 축삭) → 퍼셉트론의 구조와 대응시켜 간단히
- 맥컬록-피츠는 "자동 학습이 없었다"는 한계만 짚으면 충분
- 로젠블랫이 "학습"을 추가한 것이 왜 대단한지에 초점
- 로젠블랫의 비극적 죽음은 학생 분위기에 따라 판단

### 교사 멘트 — 뉴런에서 퍼셉트론으로

(슬라이드 #5)

> "사람은 어디에서 생각할까요? 뇌죠. 뇌에는 860억 개의 뉴런이 있어요. 뉴런이 하는 일은 의외로 단순해요 — 신호를 받고, 합산하고, 임계값을 넘으면 다음 뉴런에 신호를 보내는 거예요."

(슬라이드 #6)

> "1943년에 두 과학자가 이 원리를 수학으로 옮겼어요. '뉴런이 발화하면 1, 안 하면 0 — 이건 논리 연산이랑 같다!' 세계 최초의 인공 뉴런이 만들어진 겁니다."

> "그런데 이 모델에는 치명적인 문제가 있었어요. 학습을 못 했어요. 사람이 가중치를 직접 계산해서 넣어줘야 했거든요."

(슬라이드 #7)

> "15년 뒤, 로젠블랫이라는 과학자가 이 한계를 돌파합니다. 기계에 '학습'을 넣었어요. 데이터를 보여주면 기계가 스스로 가중치를 찾아가는 알고리즘을 넣은 거예요. 이 기계의 이름이 퍼셉트론입니다."

(슬라이드 #8 — 퍼셉트론 구조도)

> "퍼셉트론이 하는 일을 한 문장으로 말하면 — '직선 하나를 그어서 데이터를 두 그룹으로 나누는 것'이에요."

(슬라이드 #9 — 가중치 설명)

> "여기서 '가중치'라는 단어가 나오는데, 어렵지 않아요. 대입에서 '수학에 가중치 1.2'라고 하면, 수학 100점이 120점이 되잖아요. 같은 겁니다. 어떤 입력이 결과에 더 많이 영향을 미치는지를 정하는 숫자예요."

## 실습1: AND/OR 풀기 가이드 (슬라이드 #10)

### 실험 설계

**퍼셉트론 시뮬레이터 (PerceptronSimulator)**

| 항목 | 내용 |
|------|------|
| **사용 시점** | 실습1 (08-23분) |
| **예상 소요 시간** | AND 5분 + OR 5분 + 탐색 5분 = 약 15분 |
| **조작법** | w1, w2, b 슬라이더 조절 → 직선이 실시간 이동 |
| **성공 기준** | 4/4 정확도 달성 시 자동 표시 |

### 교사 멘트 (실습 전)

> "화면에 빨간 점과 파란 점이 보이죠? 여러분의 임무는 직선 하나를 그어서 빨간 점과 파란 점을 나누는 거예요."

> "w1 슬라이더를 움직이면 직선이 기울어지고, w2도 마찬가지. b를 움직이면 직선이 통째로 이동합니다. 4/4가 되면 성공! AND 모드에서 시작하세요."

### 실습 중 교사 역할

- 교실을 돌아다니며 학생들의 진행 상황 관찰
- AND를 빨리 풀면 → OR 모드로 전환하도록 안내
- AND, OR 둘 다 빨리 풀면 → "w1만 0으로 고정하면 어떻게 되는지" 탐색 과제 제시
- **관찰 포인트:** 학생들이 슬라이더를 어떻게 조절하는지 → 직관적으로 하는지, 체계적으로 하는지

### 학생 예상 반응 (실습 중)

| 반응 | 대응 |
|------|------|
| "이거 뭘 해야 하는지 모르겠어요" | "빨간 점을 한쪽에, 파란 점을 반대쪽에 놓이도록 직선을 움직이세요." |
| "4/4 됐어요!" (빠른 학생) | "좋아요! OR 모드로 바꿔보세요. AND보다 쉬울까요, 어려울까요?" |
| "수식이 뭔지 모르겠어요" | "수식은 무시해도 돼요. 직감으로 직선을 움직여서 나누면 됩니다." |
| "AND랑 OR이 뭐예요?" | "AND는 '둘 다 1이면 1', OR은 '하나만 1이어도 1'이에요. 빨간 점이 1인 경우입니다." |

### 실습 후 정리

> "AND도 됐고, OR도 됐죠? 직선 하나로 충분했어요. 생각보다 쉬웠을 거예요."

> "여기서 질문. 여러분이 방금 직접 슬라이더를 조절해서 정답을 찾았잖아요. 이걸 기계가 자동으로 할 수 있을까요?"

## 이론 설명 가이드 (슬라이드 #11~14)

### 핵심 흐름

실습에서 직접 직선을 움직여본 경험을 바탕으로, "기계가 이것을 자동으로 하는 방법"을 설명합니다. 학생이 이미 체감한 것을 이론으로 정리하는 구간이므로, 실습 경험을 자주 환기하세요.

### 교사 멘트 — 학습 규칙

(슬라이드 #11)

> "기계가 직선을 자동으로 찾는 방법이 있습니다. 규칙은 놀랍도록 단순해요."

> "'틀리면 고치고, 맞으면 냅둔다.' 이것만 반복하면 기계가 스스로 직선을 찾아갑니다."

(슬라이드 #12 — AND 학습 과정 표)

> "AND를 예로 들어봅시다. 처음에 가중치가 전부 0이에요. 아무것도 모르는 상태. 첫 데이터를 넣어요 — 틀려요. 그러면 가중치를 수정합니다. 다음 데이터 — 이번엔 맞아요. 그러면 그대로 둡니다."

> "이걸 반복하면, 결국 모든 데이터를 맞추는 가중치에 도달합니다. 여러분이 슬라이더로 찾은 그 직선을, 기계가 자동으로 찾아가는 거예요."

### 퍼셉트론 학습 애니메이션 시연 (PerceptronLearning)

| 항목 | 내용 |
|------|------|
| **사용 시점** | 이론 설명 (23-33분) 중 데모 |
| **예상 소요 시간** | 교사 시연 5분 + 학생 체험 5분 = 약 10분 |
| **기능** | "학습 시작" 누르면 직선이 스텝마다 자동 이동 |
| **해설 패널** | 매 스텝마다 가중치 변화 이유를 수식과 함께 표시 |

### 교사 멘트 (시연 중)

> "제가 먼저 보여줄게요. '학습 시작'을 누르면 직선이 스텝마다 움직여요. 오른쪽에 '왜 이 가중치가 바뀌었는지' 설명이 나오니까 같이 봐주세요."

(속도를 "느림"으로 설정하고 AND 모드 시연)

> "보세요. 첫 스텝에서 (0,0)을 넣었더니 틀렸죠? 가중치가 수정됐어요. 두 번째 스텝 — 맞아요. 그대로 둡니다. 이걸 반복하면..."

(4/4 도달 후)

> "됐죠? '틀리면 고치고, 맞으면 냅둔다' — 이것만으로 기계가 스스로 정답을 찾았어요."

> "이번에는 여러분이 직접 해보세요. AND와 OR 둘 다 해보고, 해설 패널을 읽어보세요."

### 학생 예상 반응 (이론 설명 중)

| 반응 | 대응 |
|------|------|
| "가중치가 뭐예요?" | "대입에서 '수학에 가중치 1.2' 같은 거예요. 어떤 입력이 결과에 더 많이 영향을 미치는지를 정하는 숫자입니다." |
| "편향(b)은 왜 필요해요?" | "합격 커트라인이라고 생각하세요. 기준점을 올리거나 내리는 역할이에요." |
| "이게 진짜 학습이에요?" | "좋은 질문이에요. 사람의 학습과 비교하면 아주 단순하지만, '데이터를 보고 스스로 개선한다'는 점에서 학습이라고 부릅니다." |
| "항상 정답을 찾아요?" | "직선 하나로 나눌 수 있는 문제라면 반드시 찾습니다. 수학적으로 증명됐어요. 하지만..." (XOR 복선) |

**운영 팁:**
- 속도를 "느림"으로 설정하고 교사가 먼저 시연하세요
- 해설 패널의 "왜 이 가중치가 바뀌었는가"를 학생에게 읽어보게 하면 효과적
- AND와 OR 모두 보여준 후, 학생이 직접 해보게 하세요
- "퍼셉트론 수렴 정리"까지 설명할 필요는 없음 — 교과서의 심화 박스에 있으므로 관심 있는 학생만 읽게 유도

## 실습2: XOR 도전 가이드 (슬라이드 #15~17)

### 핵심 설계 의도

이 실습이 2차시의 **핵심 경험**입니다. AND/OR의 성공 경험 직후에 XOR에서 좌절하는 대비가 클수록, 3차시 활성화함수의 임팩트가 커집니다. **학생이 충분히 좌절하지 않으면 3차시의 놀라움이 줄어드니, 최소 2~3분은 직접 시도하게 하세요.**

### 교사 멘트 (XOR 도전 전)

(슬라이드 #15)

> "자, 이번에는 새로운 데이터가 나옵니다. XOR 모드로 바꿔보세요. 같은 방식으로 직선을 그어서 나눠보세요."

**2~3분 동안 학생들이 시도하게 합니다. 교실을 순회하며 관찰.**

### 학생 예상 반응 (XOR 시도 중)

| 반응 | 대응 |
|------|------|
| "안 돼요!" (가장 흔함, 좌절) | "네, 안 되는 게 맞아요. 직선을 아무리 움직여도 4/4가 안 됩니다." |
| "버그 아니에요?" | "버그가 아니에요. 수학적으로 불가능합니다." |
| "3/4는 되는데 4/4가 안 돼요" | "좋은 관찰이에요. 3개까지는 나눌 수 있는데, 4번째가 항상 반대편에 걸려요." |
| "대각선으로 그으면 안 돼요?" | "좋은 생각이에요. 그런데 직선을 어떤 방향으로 그어도 하나는 틀리게 됩니다." |
| "점을 옮기면 안 돼요?" (장난) | "그건 반칙이에요. 데이터는 고정입니다." |

### 교사 멘트 (좌절 확인 후)

(슬라이드 #16)

> "어때요? 안 되죠? 직선을 어디에 놓아도 하나는 틀리게 돼요."

> "이건 버그가 아닙니다. 1969년에 수학적으로 증명된 거예요. 직선 하나로는 XOR을 절대 풀 수 없습니다."

**여기서 반드시 멈추고 학생 반응을 2~3초 관찰하세요.** "진짜요?" "왜요?" 같은 반응이 나오면 성공.

> "그런데 여기 '직선 2개' 버튼이 있어요. 눌러보세요."

(슬라이드 #17 — 학생들이 직선 2개로 XOR을 풀어봄)

> "됐죠? '직선을 여러 개 쓰면 된다' — 이 아이디어가 핵심이에요."

> "여러분이 방금 2분 만에 발견한 이 아이디어. 하지만 이걸 기계가 자동으로 학습하도록 구현하는 데는 20년이 걸렸습니다."

### 운영 팁

| 항목 | 내용 |
|------|------|
| **XOR 시도 시간** | 최소 2~3분, 최대 5분 (너무 오래 하면 지루해짐) |
| **좌절 충분히 느끼게** | "조금만 더 해보세요" 로 밀어주되, 3분 이상 지나면 "직선 2개" 버튼 안내 |
| **학습 시작 버튼도 시도** | XOR에서 "학습 시작"을 누르면 직선이 무한히 왔다 갔다 함 → 기계도 못 풀고 있다는 것을 시각적으로 확인 |
| **핵심 경험** | "아까는 됐는데 왜 이건 안 되지?" → 좌절 = 핵심 발견 |

## 역사 공개 가이드 (슬라이드 #18~20)

### 핵심 흐름

XOR 좌절 → 직선 2개 해결 경험 직후에, 실제 역사와 연결합니다. 학생이 방금 체험한 것이 실제 AI 역사의 핵심 사건이었다는 것을 알려주는 구간.

- 파퍼트가 Logo를 만들었다는 것은 관심 있는 학생에게만 → "교육용 프로그래밍의 시작"

## 폴백 계획 (기술 장애 시 대안 활동)

### 시나리오 A: 시뮬레이터 로딩 실패

**대안 활동 — 종이 위의 퍼셉트론 (30분)**

1. 모눈종이에 AND 데이터 4개를 좌표로 찍기: (0,0)=파랑, (0,1)=파랑, (1,0)=파랑, (1,1)=빨강
2. 자를 사용해 직선을 그어 빨간 점과 파란 점을 나눠보기
3. OR 데이터로 교체하여 반복: (0,0)=파랑, (0,1)=빨강, (1,0)=빨강, (1,1)=빨강
4. XOR 데이터: (0,0)=파랑, (0,1)=빨강, (1,0)=빨강, (1,1)=파랑 → 직선으로 나눠보기
5. "안 되는 이유"를 짝과 토의
6. "직선 2개를 쓰면 어떻게 될까?" → 2개의 직선을 그려서 XOR 해결 시도

**준비물:** 모눈종이 (학생 1인 1장), 자, 빨강/파랑 색연필 (또는 마커)

### 시나리오 B: 일부 PC만 작동

- 작동하는 PC를 사용하는 학생은 시뮬레이터 활동
- 나머지 학생은 종이 활동 → 시뮬레이터 학생의 화면을 함께 관찰
- 2인 1PC 형태로 운영 가능 (한 명이 조작, 한 명이 관찰/기록)

### 시나리오 C: 인터넷 전체 장애

**대안 활동 — 칠판 학습 규칙 따라가기 (20분)**

1. 교사가 칠판에 AND 데이터 4개 좌표를 그림
2. 학생과 함께 학습 규칙을 한 스텝씩 따라가며 가중치 변화를 기록
3. 직선이 움직이는 과정을 칠판에 그려가며 시연
4. XOR 데이터로 바꾸고, 학습 규칙이 반복해도 4/4에 도달하지 못하는 것을 확인

### 다음 차시 (3차시) 예고 포인트

> "오늘 XOR이 안 된다는 걸 발견했고, 직선을 여러 개 쓰면 된다는 것도 알았어요. 그런데 실제로 이걸 구현하려면 뭔가 하나가 더 필요합니다. 다음 시간에 그 '뭔가 하나'를 직접 켜봅니다. 스위치 하나를 켜는 순간 — 불가능이 가능으로 바뀝니다."

**교사 메모:** 2차시의 XOR 좌절 경험은 3차시 활성화함수 발견의 핵심 동기입니다. XOR이 안 된다는 좌절감이 클수록 3차시에서 활성화함수를 켤 때의 놀라움이 커집니다. 학생이 XOR을 충분히 시도하지 않고 넘어가면 3차시의 임팩트가 줄어드니, 최소 2~3분은 직접 시도하게 하세요.

### 문제 4. 퍼셉트론 학습 규칙 설명 (서술형)

**예시 답안**: 퍼셉트론은 먼저 가중치를 아무 값으로 설정한 후 데이터를 하나 넣고 예측합니다. 예측이 맞으면 가중치를 그대로 둡니다. 예측이 틀리면 가중치를 수정하는데, 1이어야 하는데 0으로 예측했으면 그때 들어온 입력값을 가중치에 더하고(w₁ += x₁, w₂ += x₂), 0이어야 하는데 1로 예측했으면 입력값을 가중치에서 뺍니다(w₁ -= x₁, w₂ -= x₂). 이것을 모든 데이터에 대해 반복하면 결국 정답에 도달합니다.

**채점 기준 (루브릭)**:

| 수준 | 기준 | 배점 |
|------|------|------|
| 상(5점) | "틀리면 고치고, 맞으면 냅둔다"의 원리를 설명하고, 틀렸을 때 가중치를 어떤 방향으로 수정하는지(더하기/빼기)까지 구체적으로 서술 | 5 |
| 중(3점) | "틀리면 고치고, 맞으면 냅둔다"는 설명했으나, 가중치 수정 방향에 대한 구체적 설명이 부족 | 3 |
| 하(1점) | 학습 과정을 언급했으나, 핵심 규칙이나 가중치 수정 방식이 부정확하거나 누락 | 1 |

### 문제 5. XOR 문제와 퍼셉트론의 한계 (서술형)

**예시 답안**: 퍼셉트론은 직선 하나를 그어서 데이터를 두 그룹으로 나누는 기계입니다. AND와 OR은 빨간 점과 파란 점이 직선 하나로 나눌 수 있도록 배치되어 있어서 퍼셉트론으로 풀 수 있습니다. 하지만 XOR은 빨간 점과 파란 점이 대각선으로 번갈아 배치되어 있어서, 어떤 방향으로 직선을 그어도 반드시 하나는 잘못된 쪽에 놓이게 됩니다. 따라서 직선 하나로는 XOR을 절대 풀 수 없습니다.

**채점 기준 (루브릭)**:

| 수준 | 기준 | 배점 |
|------|------|------|
| 상(5점) | "직선 하나로 나눈다"는 퍼셉트론의 원리를 명시하고, AND/OR은 직선 하나로 나눌 수 있는 반면 XOR은 대각선 배치 때문에 불가능하다는 점을 정확히 설명 | 5 |
| 중(3점) | XOR이 직선으로 안 된다는 것은 언급했으나, AND/OR과의 비교 또는 대각선 배치에 대한 설명이 부족 | 3 |
| 하(1점) | "XOR은 안 된다"는 결론만 제시하고, 직선과의 관계나 이유 설명이 없음 | 1 |

### 문제 7. AI 겨울의 원인 (서술형)

**예시 답안**: 퍼셉트론이 AND와 OR을 학습할 수 있어서, 원리적으로 모든 논리 연산을 배울 수 있을 것이라 기대했습니다. 그런데 XOR 하나를 학습할 수 없다는 것은 "스스로 모든 연산을 배우는 기계"라는 꿈이 깨진다는 뜻이었습니다. 퍼셉트론을 여러 층으로 쌓으면 이론상 XOR을 풀 수 있다는 것은 알려져 있었지만, 다층 구조의 가중치를 자동으로 학습시킬 방법이 없었습니다. "해결할 수 있다, 하지만 방법을 모른다"는 상황에서 연구비가 끊기고 약 20년간 AI 겨울이 시작되었습니다.

**채점 기준 (루브릭)**:

| 수준 | 기준 | 배점 |
|------|------|------|
| 상(5점) | XOR 한계가 왜 큰 문제인지(논리 연산 학습의 꿈이 깨짐)를 설명하고, 다층으로 쌓으면 가능하지만 학습 방법이 없었다는 점까지 모두 서술 | 5 |
| 중(3점) | XOR 한계의 의미 또는 다층 학습 방법 부재 중 하나만 언급하고, 나머지가 불충분 | 3 |
| 하(1점) | "XOR이 안 돼서 AI 겨울이 왔다" 수준의 단순한 서술만 있고, 구체적 이유 설명이 없음 | 1 |
